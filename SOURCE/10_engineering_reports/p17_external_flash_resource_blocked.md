# P17S External Flash Resource Blocked

## Summary

P17 tried to move the PetEgg resource path from the P16 read-only probe into a minimal package
generator and external Flash download integration. The board proved that the external NOR device and
virfat route are not completely dead, but the raw package payload read by firmware did not match the
local generated bytes. External Flash / virfat / raw NOR PetEgg resources are therefore paused and
treated as Future Scope.

Near-term PetEgg work should continue in the 2M internal Flash environment with compile-time fixtures,
the P5 test blob, or other explicitly bounded internal-resource paths.

## What Was Tried

- Generated a minimal PetEgg package containing:
  - `manifest.bin`
  - `sprites.pak`
  - `anim_table.bin`
  - combined `petegg.pkg`
- Copied the package into the SDK virfat input path as a root file named `petegg`.
- Built and downloaded firmware plus external Flash data.
- Probed `storage/virfat_flash/C/petegg` from firmware.
- Tested both SDK resource-file reads and ordinary FAT-style file reads.
- Briefly tested direct raw NOR read, which caused a soft reset and was not kept.

## Board Evidence

External Flash was detected and written during the download flow:

```text
Online external flash id: ef4018
Online external flash size: 16M
Write block:0 .
```

The PetEgg package file could be opened on the board and its size matched the generated package:

```text
info_ret=0 source=1 base=0x0 size=272 crc=0xe49a3d35 package_ret=7
```

`package_ret=7` is `PET_RESULT_BAD_VERSION`.

## Header Mismatch

The local generated `petegg.pkg` starts with the expected PetEgg manifest header:

```text
4d 52 54 50 01 00 03 00 93 f4 f7 ac 00 00 00 00
```

That is the little-endian `MRTP` magic plus version, entry count, table CRC and reserved field.

The board read the same path and size, but returned this first 16-byte header:

```text
00 01 22 64 c9 b2 44 89 32 65 cb b6 6d db b7 6f
```

Because the magic/version bytes did not match the P1/P5 resource manifest ABI, the adapter correctly
returned `PET_RESULT_BAD_VERSION`.

## API Comparison

Two runtime read paths were tested:

- `res_fopen` / `res_fread`
- ordinary `fopen` / `fread`

Both produced the same transformed header and the same `PET_RESULT_BAD_VERSION` result. This means the
problem is unlikely to be only the `res_fopen` wrapper. It is more likely related to the SDK virfat,
`fat_comm -key`, `packres`, download encryption, file mapping, or resource-loader policy.

## Direct NOR Read Result

A direct `_norflash_read_watch` style raw read experiment triggered a soft reset. That path should not
be used as a default PetEgg resource strategy and should not be revived without vendor guidance and a
small, isolated hardware-debug task.

## Current Conclusion

The observed behavior is not consistent with a completely broken SPI bus:

- the external NOR ID was readable;
- external Flash size was detected;
- external Flash data was written;
- the virfat path opened a file with the expected size.

The blocking issue is that the runtime payload is not the plain bytes generated by the PetEgg package
tool. External Flash / virfat raw package work is paused.

## Future Scope Prerequisites

Before reopening this route, confirm:

- whether `fat_comm -key default.key` encrypts or transforms ordinary file payloads;
- whether the firmware has a matching decrypt/plain-read API for such files;
- whether `flash_file_info` / `ui_res_flash_info_get` can safely expose a plain PetEgg package region;
- whether PetEgg resources should instead be represented as SDK-native `.res` entries;
- whether direct NOR reads can be made safe on this board, preferably with vendor or solution-provider
  guidance.

## Current Safe Direction

This pause does not block:

- Pet2D scene handoff work;
- internal or compile-time small resources;
- the P5 in-memory resource manifest/test blob path;
- internal save/syscfg work;
- engineering test menu work.

Continue to keep the following disabled in committed source:

```text
real_resource_package_available = 0
external_flash_resource_enabled = 0
PET_JIELI_ENABLE_REAL_LCD_FLUSH_POC = 0
real_lcd_flush_enabled = 0
pet2d_runtime_enabled = 0
```

NFC, audio/speaker and real BLE two-board validation remain Future Scope for the current hardware cycle.
