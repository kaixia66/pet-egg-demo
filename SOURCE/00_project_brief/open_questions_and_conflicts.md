# Open Questions and Conflicts

> 本文件记录碰碰宠物蛋 PRD、MVP-A、UI 设计、资源生成和 SDK 工程之间的冲突、待确认点和当前执行口径。  
> CodeX 在遇到需求不一致时，应先查本文件，不要凭空选择更复杂方案。

---

## 1. 冲突处理总原则

当不同文档之间出现冲突时，MVP-A 当前执行优先级如下：

1. 用户当前任务中的明确指令；
2. `sdk/source/CODEX_CONTEXT.md`；
3. `sdk/source/00_project_brief/mvp_a_scope.md`；
4. 本文件；
5. MVP-A UI / 资源设计文档；
6. 软件版 PRD；
7. 硬件版 PRD；
8. 养成体系 PRD；
9. 宠物体系 PRD；
10. 卡牌 / 卡包体系 PRD；
11. 投资人版 PRD。

核心原则：**MVP-A 是开发板 Demo，不是完整商业版。**

## 2. 已知关键冲突

## 2.1 SD 内容卡 vs 取消 SD 卡

### 冲突描述

历史 PRD 曾采用 SD 内容卡模型：

- 当前插入 SD 卡决定当前宠物；
- 宠物数据跟随 SD 卡；
- 设备卡包跟随设备；
- 换 SD 卡切换宠物 / 世界；
- 对战时当前 SD 宠物直接出战。

后续 portable hardening 和 Jieli port 阶段已确认新产品架构：

- 数据全部保存在设备中；
- 设备本地最多 `PET_MAX_COUNT = 18` 只宠物；
- 内容卡指 NFC 实体卡；
- NFC 内容卡只激活本地或外置 Flash 预置内容；
- NFC 内容卡不承载图片、动画、宠物资源或道具资源；
- 家园、卡包、装备、NFC 激活记录都设备本地化。

### MVP-A 当前执行口径

MVP-A 和 P13 Jieli minimal port 均不实现 SD 内容卡系统。

当前建议执行：

```text
MVP-A 以开发板 Demo 口径为准：
- 单宠青龙主线；
- 设备本地存档；
- 不做 SD 商品卡；
- 不做宠物数据跟 SD 卡走；
- 不做 SD world manifest；
- NFC 读卡入卡包或激活本地预置内容；
- 如 SDK 已有 SDFILE/NOR/NAND/VM 等资源路径，只作为底层存储/资源机制使用，不恢复 SD 商品内容模型。
```

### CodeX 规则

- 不要实现设备最多 5 只宠物的旧口径；
- 不要恢复宠物数据跟 SD 卡走；
- 不要恢复 SD 内容卡或 SD world manifest；
- 不要把 NFC 内容卡设计成资源载体；
- 若任务涉及宠物数据归属，按设备本地数据口径处理。

## 2.2 单宠青龙主线 vs 18 只灵兽池

### 冲突描述

宠物体系 PRD 定义了 18 只灵兽：

- 灵木 6 只；
- 烈火 6 只；
- 玄水 6 只；
- Stage4 / Stage5 完整形态；
- 稀有度：传奇、珍稀、普通。

MVP-A 当前目标则是单宠青龙成长 Demo。

### MVP-A 当前执行口径

```text
MVP-A 只实现青龙主线：
Stage0 灵核 / 灵蛋
Stage1 包子
Stage2 灵木成长期
Stage3 灵茧
Stage4 青龙宝宝
Stage5 终极青龙
```

18 只灵兽只作为后续内容扩展和视觉风格参考。

### CodeX 规则

- 不要生成 18 只灵兽的数据结构或页面；
- 不要实现完整灵兽随机抽取；
- 不要实现完整稀有度概率；
- 可以保留字段扩展位，如 species、attribute、rarity；
- 当前 UI / 资源优先接入青龙与岩灵 Boss。

## 2.3 完整养成系统 vs MVP-A 快速成长

### 冲突描述

养成体系 PRD 定义了完整日常照料：

- 每日 3–5 次短互动；
- 每日 3 个基础任务 + 1 个随机任务；
- 喂食、陪伴、清理、灵核修复；
- 沉睡与重新唤醒；
- CareScore、BondScore、LevelCoefficient；
- Fatigue、SleepRisk。

MVP-A 只需要演示成长和交互闭环。

### MVP-A 当前执行口径

MVP-A 做简化养成：

- 喂食；
- 陪伴；
- 训练；
- 成长进度；
- 测试模式快速成长；
- 可选简化沉睡 / 恢复提示；
- 不做完整每日任务系统。

### CodeX 规则

- 不要实现完整日常任务引擎；
- 不要实现复杂 Fatigue / SleepRisk；
- 不要实现长期真实时间衰减，除非用户明确要求；
- 可使用模拟时间或 debug 快速成长；
- 存档字段可预留，但 UI 不展开复杂状态。

## 2.4 商业卡牌系统 vs NFC Demo 卡包

### 冲突描述

卡牌 / 卡包 PRD 定义了完整商业卡牌系统：

- 宠物卡；
- 食物卡；
- 陪伴卡；
- 装备卡；
- 家园卡；
- 图鉴；
- 纸卡轻玩法；
- 主题半随机包；
- 稀有度概率；
- 盒级保底；
- 赠送；
- 家长友好机制。

MVP-A 只需要 NFC 读卡入卡包验证。

### MVP-A 当前执行口径

MVP-A NFC / 卡包只做技术验证：

- 读取 NFC Tag；
- 识别 Demo 卡；
- 加入本地卡包；
- 展示卡牌；
- 可选使用一张食物 / 能量 / 装备 Demo 卡；
- 不做完整商业概率；
- 不做纸卡玩法；
- 不做完整图鉴；
- 不做家园卡。

### CodeX 规则

- 不要实现完整卡牌经济；
- 不要实现抽包概率；
- 不要实现盒级保底；
- 不要实现纸卡三数值；
- 不要实现家园卡布置；
- 可以预留 cardType 枚举，但 UI 只展示 MVP-A 必需卡；
- 若用户要求“卡包”，默认是 Demo 卡包而不是商业版完整卡包。

## 2.5 装备 / 对战系统 vs 合作岩灵 Boss

### 冲突描述

软件 PRD 中包含 1v1 对战：

- 当前 SD 宠物直接出战；
- 对战前最多选 3 张装备；
- 属性克制；
- QTE；
- 装备加成；
- 最终伤害展示。

MVP-A 主要目标是合作岩灵 Boss 技术验证。

### MVP-A 当前执行口径

MVP-A 优先实现合作 Boss，而不是完整 1v1 商业对战：

- 两台设备连接；
- 进入合作 Boss；
- 双方 QTE；
- Boss HP 或阶段变化；
- 胜负 / 奖励结算；
- 简化装备或不接装备。

### CodeX 规则

- 不要优先实现完整 1v1；
- 不要实现复杂装备选择；
- 不要实现完整属性克制 UI；
- 可以复用 QTE 和伤害展示思想；
- Boss 战斗逻辑以稳定联机和演示为主。

## 2.7 UI 复杂度冲突

### 冲突描述

完整 PRD 包含很多状态、变量、卡牌、图鉴、任务和列表，但目标设备是 1.5 英寸小屏，MVP-A 还有圆屏安全区要求。

### MVP-A 当前执行口径

UI 只表达核心动作：

- 顶部短标题；
- 中央主视觉；
- 底部唯一操作气泡；
- 每页一个核心动作；
- 不显示完整公式；
- 不显示复杂数据表；
- 不做长列表。

### CodeX 规则

- 不要在页面放太多文字；
- 不要把 PRD 表格直接做成 UI；
- 数值尽量用图标、进度和短反馈；
- 对战只逐步弹出“完美操作”“能量提升”“造成伤害”等儿童可理解反馈。

## 2.8 资源包 vs Git 仓库体积

### 冲突描述

资源生成流程会产生大量 PNG 序列帧、Sprite Sheet、ZIP 包、manifest 和 CSV。直接放入 Git 可能导致仓库过大。

### MVP-A 当前执行口径

建议：

- manifest / csv / json / md 放 Git；
- 关键少量参考图可放 Git；
- 大量 PNG 序列帧和 ZIP 资源包可先放外部存储或 release；
- 若必须放入 SDK 资源工程，应只放最终工程需要的压缩 / 转换后资源。

### CodeX 规则

- 不要把大 ZIP 直接提交到 source；
- 不要把所有生成中间文件提交；
- 先生成 `resource_index`；
- 确认资源路径和命名后再接入 UI 工程。

## 3. 当前未决问题

### 3.1 MVP-A 是否使用真实 SD 卡？

状态：已取消 SD 内容卡产品口径。

建议：

- 不实现 SD 商品卡、SD world manifest 或宠物数据跟 SD 卡走；
- 如 SDK 内部仍有 SDFILE/NOR/NAND/VM 宏或资源机制，只作为底层工程实现细节；
- P13 以后资源和存档以设备本地或外置 Flash 预置内容为准；
- NFC 内容卡只携带小 payload，用于激活本地预置内容。

### 3.2 NFC 卡是否使用安全标签？

状态：MVP-A 阶段可不完整实现。

建议：

- Demo 可以先使用普通 NFC Tag；
- 代码结构预留 UID、Type、Payload、Signature、UsedFlag；
- 安全标签、防复制、写入锁定作为商业版 / 后续硬件验证任务。

### 3.3 BLE 合作 Boss 同步粒度

状态：待工程验证。

可选：

1. 同步输入指令；
2. 同步 QTE 结果；
3. 同步 Boss HP；
4. 同步随机种子 + 双端本地计算。

MVP-A 建议优先稳定：

- 若时间紧，同步 QTE 结果和 Boss HP；
- 若要更接近最终方案，同步随机种子和指令。

### 3.4 存档位置

状态：取决于 SDK 当前能力。

建议：

- 优先用 SDK 已有本地持久化能力；
- 不使用 SD 内容卡作为宠物数据归属；
- 后续 Jieli port 使用 VM/Flash A/B slot 或等价本地持久化；
- 必须有版本号和恢复策略；
- 不要为了完整商业版数据模型阻塞 MVP-A。

### 3.5 UI 资源格式

状态：需根据当前 SDK UI 工具确认。

待确认：

- PNG 支持格式；
- 透明通道支持；
- Sprite Sheet 支持；
- 帧动画配置方式；
- UI 工程资源 ID 生成方式；
- 454×454 到设备屏幕的适配方式。

## 5. CodeX 遇到冲突时的响应方式

当 CodeX 发现冲突，不要直接按更复杂的 PRD 实现。应输出：

```text
发现冲突：
- 文档 A 说：
- 文档 B 说：
- MVP-A 当前建议采用：
- 原因：
- 是否需要用户确认：
```

如果冲突不影响当前任务，应按 MVP-A 简化口径继续执行。

如果冲突会导致数据结构、页面结构或工程路径大改，应停止修改并请求确认。

## 6. 当前执行口径摘要

CodeX 当前应默认采用：

```text
MVP-A = 单宠青龙开发板 Demo
硬件 = 4 键 + 摇一摇 + 顶部 NFC + BLE + 本地存档
UI = 454×454 圆屏安全区 + 顶部短标题 + 中央主视觉 + 底部唯一操作
NFC = 读卡入 Demo 卡包
BLE = 碰一碰后进入合作岩灵 Boss
养成 = 简化喂食 / 陪伴 / 训练 / 成长
资源 = 青龙 Stage0–Stage5 + 岩灵 Boss + UI 组件
存档 = 设备本地保存 Stage / 成长 / 卡包 / Boss 结果
不做 = 完整商业版多宠、完整卡牌经济、复杂对战、App、云端、联网
禁止 = SD 内容卡、SD world manifest、宠物数据跟 SD 卡走
```
